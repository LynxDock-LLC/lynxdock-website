14. PRIVACY
For community chat and voice, the app connects to the community server
address you enter and, for voice, to the media service that server's
operator runs and to the connection helpers that server gives it: by
default Google's public STUN server, and the operator's TURN server if
TURN is enabled. LynxDock Host makes further contacts only as its operator
sets it up.
   Components. When the operator turns voice on, the Host downloads
LiveKit from LiveKit's GitHub release and, if TURN is enabled, coturn from
LynxDock's download storage, and checks each download against a signed
manifest shipped in the build before using it. Those hosts see the
ordinary connection details of the download.
   External address. To learn the server's public address, the Host asks
public STUN servers (Google's and Cloudflare's) when the operator uses
"Make reachable", and each time voice starts with TURN enabled, including
an automatic start the operator has switched on. The LiveKit configuration
the Host writes also sets LiveKit to discover the public address itself
when it starts, and names no STUN servers; according to LiveKit's
documentation, LiveKit then uses STUN for this, and which servers it
contacts has not been verified. "Make reachable" also asks the operator's
router for a UPnP port mapping.
   Catalogue. If the operator enables an optional catalogue provider, the
server, not any member's device, fetches reference data from it.
   Installation. If Microsoft's WebView2 runtime is missing from your PC,
either installer downloads Microsoft's WebView2 bootstrapper from
Microsoft during installation.
   Updates. Neither the app nor the Host checks for, downloads or installs
application updates; you install a new build yourself from LynxDock's
download location. The Host's "Update the server" setting installs a
server program from a file the operator chooses and never fetches one. The
component downloads above are not application updates.
   Licence and key checks. The licence and key checks are local: when
it starts, the app or the Host compares the acceptance record on your
device with this build's licence ID, version and text hash, checks that
your 18+ declaration is recorded, and verifies the stored beta access
key's signature and this build's built-in list of withdrawn key IDs.
Nothing is verified online and no licence or key information is sent.
When you accept, the app or the Host stores a record in your local user
profile on that device: the licence ID and version, the text hash, your
18+ declaration, the time of acceptance and the app version; earlier
acceptances stay in the same record. When you enter your access key, it
is stored in the same place. The acceptance record and the stored key
contain no name, account, email address or device identifier; the key
itself carries only its issue date, a random key ID and technical
fields.
   Issuance records. LynxDock emails your personal access key to you and
keeps an issuance record linking that key's ID to your email address,
together with the issuance correspondence, while your participation is
active and afterwards for up to one year, with a recorded participation
end date; the record and correspondence are then deleted. A community
operator never receives or relays your key. The LynxDock website privacy
notice (https://lynxdock.app/privacy/) gives the details.
   Neither the app, the Host nor the server sends unsolicited usage or
crash telemetry to LynxDock. The app can automatically retry a bug report
that you previously reviewed and approved, to the destination configured
at the time, as described below. LynxDock does not operate your community
server; its data is handled by the server's operator.
   Beyond the contacts described above, information leaves your device
only when you choose to send it. You can copy diagnostics and send them
yourself. The app's bug-report feature sends a report only after you have
reviewed and approved it, and only if a report destination has been set on
that PC by an environment variable; no destination is set by default, and
without one reports can only be reviewed and exported. A report you
approve stays queued until it is delivered: the app retries it at each
later start, at most five attempts in all, while a destination is set, and
sends it to the destination set at that time. If you acknowledge the
participation requirements on LynxDock's tester page, the details you
enter there are submitted to Formspree, the form service that page uses.
If you write to LynxDock, we keep that correspondence to deal with it. The
privacy notes distributed with each build give the details.
